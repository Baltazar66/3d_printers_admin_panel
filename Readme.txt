Инструкция по переносу проекта «Сканер 3D-принтеров» на новый ПК
Ниже — пошаговая инструкция для «чистой» Windows: установка Node.js, перенос файлов, запуск, а также настройка новых розеток Tuya (откуда брать параметры и как дописывать devices.json).

📦 Шаг 1: Подготовка файлов на старом ПК
Соберите в одну папку все файлы проекта:

Файл	Назначение
3d printers main.html	Интерфейс сканера
start.js	Сервер, прокси, управление розетками
devices.json	Настройки: облако Tuya, диапазон IP, розетки
Запуск сканера.bat	Bat-файл для ярлыка (создаётся вами)
package.json	Создаётся npm (содержит зависимости)
node_modules/	Папка с установленными пакетами (можно не переносить — установите заново на новом ПК)
Скопируйте папку на USB или в облако.

🖥️ Шаг 2: Установка Node.js на новом ПК
Node.js не входит в Windows и не устанавливается автоматически .

Откройте nodejs.org → скачайте LTS-версию (.msi для Windows).

Запустите установщик. На шаге Custom Setup обязательно оставьте галочку «Add to PATH» (она включена по умолчанию).

Завершите установку.

Закройте и снова откройте командную строку (PowerShell/CMD). Это важно — изменения PATH применяются только в новых окнах.

Проверьте:

powershell
node --version
npm --version
Если отобразились версии — Node.js установлен корректно .

Если node не распознаётся, значит PATH не подхватился. Переустановите Node.js, явно отметив «Add to PATH», либо добавьте C:\Program Files\nodejs\ в переменную Path вручную .

📂 Шаг 3: Перенос файлов и установка зависимостей
Скопируйте папку проекта на новый ПК (например, D:\3dprinter_status).

Откройте PowerShell/CMD, перейдите в папку:

powershell
cd D:\3dprinter_status
Установите зависимости:

powershell
npm install @tuya/tuya-connector-nodejs
Если npm в PowerShell выдаёт ошибку политики выполнения, используйте npm.cmd:

powershell
npm.cmd install @tuya/tuya-connector-nodejs
Проверьте, что пакет установлен:

powershell
npm.cmd list @tuya/tuya-connector-nodejs
📄 Шаг 4: Настройка devices.json для новой/существующей розетки
devices.json — центральный файл настроек. Пример структуры:

json
{
    "tuya_cloud": {
        "base_url": "https://openapi.tuyaeu.com",
        "access_id": "ВАШ_ACCESS_ID",
        "access_secret": "ВАШ_ACCESS_SECRET"
    },
    "scan": {
        "ip_range": "192.168.0.1-254",
        "rescan_after_plug_on_sec": 90
    },
    "plugs": [
        {
            "id": "bf255c0dca5b80af1e2a7v",
            "name": "Кенгурун 1",
            "switch_code": "switch_1",
            "printer_ip": "192.168.0.104"
        }
    ],
    "plug_poll_sec": 15
}
🔑 Где брать параметры для новой розетки
tuya_cloud.access_id и access_secret
Эти данные выдаются при создании облачного проекта на платформе Tuya Developer (iot.tuya.com):

Войдите на iot.tuya.com.

Слева: Cloud → Cloud Project → Project Management (или «Проекты»).

Создайте проект (если ещё нет). Development Method — обязательно Smart Home (全屋智能) .

После создания в разделе Authorization Key (授权密钥) скопируйте Client ID (= access_id) и Client Secret (= access_secret) .

В том же проекте перейдите на вкладку Devices → Link Tuya App Account → Add App Account, отсканируйте QR-код в приложении Smart Life. После привязки в разделе All Devices появятся ваши устройства .

plugs[].id (Device ID)
На той же вкладке All Devices в облачном проекте напротив розетки отображается Device ID — скопируйте его .

plugs[].switch_code
Обычно switch_1 (или switch). Если после запуска в логах start.js появится сообщение DP "switch_1" не найден. Доступные: ... — замените на указанный там код.

plugs[].printer_ip
Локальный IP принтера. Нужен для защиты от выключения во время печати (сервер проверяет статус Moonraker перед отправкой off). Если проверка не нужна — можно не указывать или оставить null.

IP-адрес розетки (для devices.json не требуется)
В текущей версии проекта управление идёт через Tuya Cloud API, поэтому локальный IP розетки в devices.json не нужен. Это упрощает настройку: не нужно искать IP в роутере и беспокоиться, что он изменится после перезагрузки.

Приложение Smart Life показывает публичный IP, а не локальный . Если бы вы использовали локальный протокол (@apocaliss92/nodetuya), IP пришлось бы искать через роутер или tinytuya scan. Но с облачным управлением это не требуется.

Добавление второй и последующих розеток
Просто добавьте ещё один объект в массив plugs:

json
"plugs": [
    { "id": "ID_РОЗЕТКИ_1", "name": "Кенгурун 1", "switch_code": "switch_1", "printer_ip": "192.168.0.104" },
    { "id": "ID_РОЗЕТКИ_2", "name": "Кенгурун 2", "switch_code": "switch_1", "printer_ip": "192.168.0.105" }
]
Каждая розетка должна быть привязана к тому же облачному проекту Tuya и отображаться в All Devices .

🚀 Шаг 5: Запуск
В папке проекта выполните:

powershell
node start.js
В консоли должно появиться:

text
Tuya Cloud: https://openapi.tuyaeu.com
Загружено розеток из devices.json: 1
Tuya Cloud: токен получен.
Розетка "Кенгурун 1" доступна через облако, состояние: false
Запущен периодический опрос розеток (15 с).
Открываю браузер...
Браузер откроется на http://localhost:8000/.

🔗 Шаг 6: Ярлык для запуска (по желанию)
Создайте Запуск сканера.bat в папке проекта:

bat
@echo off
cd /d "%~dp0"
node start.js
pause
Правый клик по .bat → Отправить → Рабочий стол (создать ярлык).
